# 台灣好物商場　完整需求規格

Nov 23, 2026 · @Prome Theus

本文件整合第一～六階段的需求。v6.0.2 已完成第一～六階段全部程式，並在本機 MariaDB 與 PHP 8.3 測試通過（241 項，見 TEST_REPORT.md）；實作時的補充與差異見文末第 40 節。

## 1. 系統範圍與六個階段

商場分六個階段建置，每個階段都有自己的增量 SQL 與 `config.php` 開關，可以只裝到某一階段。第四階段只有貨到付款；第六階段加入模擬線上支付與超商取貨，不串接真實金流。

| 階段 | 內容 | 開關 | 狀態 |
| --- | --- | --- | --- |
| 第一階段 | 會員註冊與驗證、登入、忘記密碼、會員中心；商品瀏覽；後台會員、商品、分類、標籤、庫存、異動紀錄 | —（必備） | 已交付 |
| 第二階段 | 購物車 | `$enable_cart` | 已交付 |
| 第三階段 | 會員行為事件、原加入價格批次、六項排行、每月分區與封存 | `$enable_behavior` | 已交付 |
| 第四階段 | 地址簿、運費規則、結帳、訂單、出貨與收件、退換貨、會員等級 | `$enable_orders` | 已交付 |
| 第五階段 | 公開資訊與購物須知、Cookie 同意與 Consent Mode v2、自訂程式碼、寄信紀錄、備份與還原、管理員 IP 白名單、辨識碼、管理員權限模組、管理總覽、聯繫表單與客服中心 | `$enable_ops` | 已交付 |
| 第六階段 | 會員刪除帳號與匿名化、SEO、結構化資料與社群標記、GA4 電子商務 dataLayer、商品圖片、商品規格、模擬線上支付與超商取貨、維護模式、錯誤紀錄、寄信額度、資料清理 | `$enable_launch` | 已交付 |

- 開關依賴：第三階段需要購物車，第四階段需要購物車；第五階段只需要第一階段；第六階段需要第四、五階段。
- 不含：真實金流與物流 API、電子發票、優惠券、友善網址、社群登入、同一訂單分批出貨、售後照片上傳。

## 2. 部署環境與共通規則

程式部署在 InfinityFree 免費主機，不能依賴資料庫 `TRIGGER`、`EVENT`、排程或常駐服務；需要定時的工作一律改成「開啟頁面時被動檢查」。

**環境**

- PHP 7.4～8.x、PDO 參數化查詢；MariaDB 10.5 以上（主機為 11.4），全部資料表 InnoDB、utf8mb4。
- PHP 與資料庫連線都用台灣時間（UTC+8）。
- 寄信用 PHPMailer 透過外部 SMTP（例如 Gmail 應用程式密碼）；InfinityFree 不提供 SMTP，PHP `mail()` 受限。

**`config.php`**

- 資料庫連線、SMTP 帳密、商場基本網址 `$site_url`（含子目錄）只在這裡設定一次；交付 `config.sample.php` 範本，不含正式帳密。
- 各階段開關、`$app_debug`（正式環境必為 false）。
- 緊急開關：`$disable_custom_code`（跳過自訂程式碼）、`$disable_admin_ip_allowlist`（暫停 IP 白名單），供設定錯誤致無法進入後台時在主機上修改。

**共通規則**

- 所有入口載入 `app.php`，由它載入 `config.php`、建立 PDO 連線、Session 與共用函式。
- 寫入一律 POST，檢查 CSRF 權杖；用 `row_version` 拒絕舊頁覆寫；需要填寫的表單另加辨識碼（第 21 節）。
- 每個受保護入口與寫入都從資料庫核對會員狀態與權限（第五階段起依模組權限，第 22 節）；拒絕存取回應 HTTP 403，提供登入與「登出並切換帳號」。
- 後台寫入經 `admin_transaction()`：先鎖 `shop_write_lock`（id=1）、再鎖操作者、再鎖目標；異動前後與異動紀錄在同一筆交易內完成，紀錄排除密碼雜湊與憑證。
- 金額用 DECIMAL 與整數「分」計算，不用浮點數。
- HTML 輸出編碼；使用者畫面不顯示例外細節，詳情寫入伺服器錯誤紀錄。
- Session Cookie 使用 HttpOnly、SameSite=Lax，HTTPS 時加 Secure；登入成功更新 Session ID。
- 回應標頭：`X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: same-origin`。

## 3. 會員帳號（第一階段）

會員以 Email 註冊、驗證後啟用；驗證信與重設密碼連結都是隨機憑證、資料庫只存 SHA-256 雜湊、30 分鐘有效、使用後立即失效。

| 流程 | 規則 |
| --- | --- |
| 註冊 | 姓名 1～50 字、Email（轉小寫、唯一）、密碼與確認密碼；密碼 8～72 位元組，以 `password_hash` 儲存 |
| 驗證與補寄 | 新帳號為待驗證；驗證成功後啟用；補寄會取代舊憑證；停權或軟刪除帳號不能經驗證重新啟用；不論帳號是否存在都顯示相同訊息 |
| 登入 | 只有啟用、未軟刪除的帳號可登入；同一 Session 連續失敗 5 次需等 1 分鐘 |
| 登出 | POST 加 CSRF；清除登入狀態與 Session；購物車保留 |
| 忘記密碼 | 只為啟用、未刪除的會員產生連結；重新申請取代舊憑證；不論帳號狀態或寄信結果都回覆相同訊息；同一 Session 60 秒內不重寄 |
| 設定新密碼 | 送出時重新檢查帳號、憑證與期限，以同一筆條件更新並清除憑證；輸入錯誤時保留表單，憑證不消耗 |
| 會員中心 | 修改姓名、變更密碼（驗證舊密碼）；第四、五階段加收件資料、我的訂單與客服中心；不能自行修改權限、狀態、等級或累積消費 |

- 會員狀態：`0` 停用、`1` 啟用、`2` 待驗證；另有 `deleted_at` 軟刪除。
- 等級：一般、銀卡、金卡、鑽石，與管理權限分開儲存；第四階段起依累積消費自動計算（第 14 節）。
- 返回位置 `return_to` 只接受同目錄的 `product.php?id=正整數`；註冊、驗證、補寄與登入都會傳遞，無效時回到首頁。

## 4. 商品、分類、標籤與庫存（第一階段）

訪客可以瀏覽上架商品；後台管理商品、分類、標籤與庫存，商品不提供刪除，以下架處理。

**前台**

| 頁面 | 行為 |
| --- | --- |
| `index.php` | 首頁：搜尋框、分類入口、最新上架商品 |
| `products.php` | 上架商品列表；名稱或 SKU 搜尋、分類與標籤篩選、分頁；無結果時顯示提示 |
| `product.php?id=` | 名稱、SKU、說明、分類、標籤、價格、庫存；不存在回應 404；下架商品保留網址並顯示下架提示；圖片用共用示意圖 |

**後台**

- **商品**：名稱、說明、SKU（唯一）、單一分類、多個標籤、價格、上下架；第四階段加「運費規則」。建立商品時一併建立庫存。
- **分類、標籤**：新增、修改、刪除；名稱唯一；已被商品使用時不能刪除。
- **庫存**：設定數量或增減，數量必須 ≧ 0；鎖定順序為商品 → 庫存。
- **異動紀錄**：依類型與資料編號查詢，顯示異動前後。

## 5. 後台會員管理與管理者保護（第一階段）

管理者可以查詢與管理會員，但不能對自己或較早註冊的管理者執行受保護操作。

- **查詢**：分頁，依編號、姓名、Email、狀態（含已刪除）篩選。
- **操作**：修改姓名與等級、變更管理權限、啟用、停權、軟刪除、補寄驗證信；第四階段加「鎖定等級」與該會員的訂單。
- **受保護操作**（停權、刪除、變更管理權限）：不能對自己執行；不能對註冊時間早於或等於自己的其他管理者執行。
- **待驗證會員**：須完成 Email 驗證才能啟用；可補寄驗證信、修改姓名與等級、在規則內調整權限或刪除。
- **停權會員**：已完成 Email 驗證者才能重新啟用。
- **軟刪除**：刪除後停用一般管理操作，並清除驗證與重設憑證。
- 管理選單的 HTML 只輸出給管理者；第五階段起改為模組權限（第 22 節），設定 IP 白名單後另需符合 IP（第 20 節）。

## 6. 購物車（第二階段）

每位會員一台購物車，同商品累加成一筆明細；購物車不預留也不扣減庫存。

- **加入**：在商品詳情頁，數量預設 1。可再加入件數 = 目前庫存 − 購物車已有件數；下架、缺貨或超出時停用按鈕並說明原因。送出時伺服器重查商品與庫存。
- **成功後**：POST → 303 → GET 回到原商品頁，顯示商品名稱、本次件數、累計件數與「瀏覽購物車」；重新整理不重送。
- **訪客**：按「加入購物車」前往登入頁；登入或註冊驗證登入後回到原商品頁；直接開啟購物車回應 403。管理者代發的驗證信不帶返回位置。
- **購物車頁**：名稱與連結、SKU、目前單價、庫存、數量、小計、總金額；可改數量、移除、繼續購物；第四階段加「前往結帳」。
- **下架或缺貨**：保留明細並標示原因，停用數量更新，仍可移除。
- **交易**：鎖定順序為會員 → 購物車 → 商品 → 庫存 → 明細；兩個分頁同時加入同一商品仍正確累加；用 `row_version` 拒絕舊頁；只能操作自己的明細。
- **資料表**：`carts`（每會員唯一）、`cart_items`（購物車與商品唯一、數量 > 0、外鍵完整）。

## 7. 會員行為分析、分區與封存（第三階段）

系統記錄會員的瀏覽與購物車事件，產生六項商品排行，並依月份分區與封存。行為紀錄屬站內會員服務紀錄，**不受 Cookie「分析統計」同意控制**（決策 23）。

**事件**

| 事件 | 寫入時機 |
| --- | --- |
| `view_product` | 已登入、啟用、未刪除的會員以 GET 開啟上架商品（含缺貨）；加入購物車後自動返回的那一次不計（一次性標記，5 分鐘）；訪客、列表、不存在或下架商品不計 |
| `add_to_cart` | 成功加入，每次操作一筆 |
| `update_cart` | 成功修改數量且前後不同 |
| `remove_from_cart` | 成功移除整筆明細；結帳清空購物車不寫入 |

- 分析工作階段 `session_key` 獨立隨機產生；前台閒置滿 30 分鐘、重新登入或切換會員時另開；後台活動不延長。
- 事件保存當時的會員等級與商品分類；瀏覽事件寫入失敗只記錯誤、頁面照常顯示；購物車事件與明細、價格批次同一筆交易。
- **原加入價格批次**：加入或調增時以當時單價新增批次；調減與移除依先進先出（FIFO）扣回，`unit_price` 為 NULL、`amount_delta` 記扣回金額負值。無批次的舊明細首次操作時以當下售價補建 `opening` 批次。

**六項排行**（各取前十名，同值依商品編號）：瀏覽次數、不重複瀏覽工作階段、加入購物車次數、移出購物車次數、加入購物車淨件數、加入購物車淨金額。前四項只列大於零；後兩項可選正值、全部或負值；有金額未知事件的商品排除於淨金額排行。

**報表查詢**：期間（台灣時間全天）、事件當時分類、資料來源（線上／封存／合併）、會員範圍（全部／指定會員／目前或事件當時等級）、行為類型、淨值模式；初次開頁不自動查詢；明細每頁 50 筆。

**分區與封存**

- 線上事件表與舊共用封存表依 `event_time` 按月分區，另有 `p_future`；「檢查並補建月份」補到本月加 6 個月，保留預備分區資料。
- 封存已結束的月份到 `member_behavior_archive_YYYYMM`：每批 200 筆、可自動接續與「本批完成後暫停」、衝突即停止並保留來源、核對筆數與內容後才移除來源；狀態與錯誤寫入 `behavior_archive_months`，中斷可接續。
- 報表依「主表 → 舊共用表 → 月份表」按 `(event_id, event_time)` 去重；已登記的月份表遺失須報錯；維護頁與報表共用資料庫命名鎖。
- 一次性轉換 SQL：既有購物車建立 `opening` 批次、舊 `product_view_logs` 轉入事件表；重跑不重複。

## 8. 會員地址簿（第四階段）

會員中心新增「收件資料」，每人最多 10 筆，結帳與換貨時從中選取。

| 欄位 | 規則 |
| --- | --- |
| 收件人 | 1～30 字 |
| 電話 | 數字與「-」，8～20 字；貨到付款需聯絡得到，建議填手機 |
| 郵遞區號 | 3～6 位數字 |
| 縣市、鄉鎮區 | 各 1～10 字 |
| 詳細地址 | 1～100 字 |
| 預設地址 | 每人最多一筆；第一筆自動設為預設 |

- 刪除採軟刪除；選取的地址若在送出前被刪除，送出會被拒絕並要求重選。
- 訂單、出貨單與換貨售後單都存收件資料快照；之後修改或刪除地址簿不影響既有單據。
- 只能存取自己的地址；他人的地址回應 404。

## 9. 運費規則（第四階段）

整筆訂單只收一次運費，取適用規則中最高的運費；沒有設定規則的商品免運。

- **全站模式** `shipping_mode`：`all_free` 全部免運，或 `by_rule` 依商品規則計算。
- **運費規則**：名稱（唯一）、運費（≧ 0）、滿額免運門檻（可空，空值代表不因金額免運）、啟用狀態。
- **商品編輯頁**可選一條啟用中的規則，不選就是免運；停用的規則視同免運；有商品使用中的規則不能刪除。
- **貨到付款手續費**：全站設定，預設 0 元，每筆訂單加收一次。

`by_rule` 計算步驟：

1. 商品小計 = Σ 單價 × 數量。
2. 找出訂單內各商品套用的啟用規則。
3. 規則有門檻且商品小計 ≧ 門檻，這條規則不收費。
4. 運費 = 其餘規則中最高的運費；都不收費時為 0。

範例：規則 A「一般宅配」80 元、滿 1,000 元免運；規則 B「大型商品」150 元、無門檻。

| 購物車內容 | 商品小計（元） | 運費（元） |
| --- | --- | --- |
| 只有 A 商品 | 800 | 80 |
| 只有 A 商品 | 1,200 | 0 |
| A 商品 + B 商品 | 1,200 | 150（A 已滿額，B 無門檻） |
| A 商品 + 未設規則商品 | 600 | 80 |
| 只有未設規則商品 | 300 | 0 |

訂單總額 = 商品小計 + 運費 + 貨到付款手續費。訂單存下當時的運費、收費規則名稱與手續費。

## 10. 結帳（第四階段）

購物車按「前往結帳」→ 結帳頁選地址並確認 → 送出後在同一筆交易內成立訂單、扣庫存、清空購物車並產生待出貨的出貨單。

**結帳頁**

- 明細（目前售價）、商品小計、運費、手續費、總額；付款方式固定「貨到付款」；第六階段增加配送與付款選擇（第 31 節）。
- 選收件資料（預設選中預設地址），沒有地址時可直接新增；選填備註最多 200 字。
- 顯示退換貨期限與申請方式，並連結「退貨條款」「使用者購物須知」「個資保護聲明」（第 15 節）。
- 購物車有下架、缺貨或超過庫存的品項時，停用送出並列出原因。

**送出訂單（同一筆交易，任一步失敗全部回復）**

1. 重新核對會員狀態、結帳憑證與地址歸屬。
2. 依固定順序鎖定：會員 → 購物車 → 商品 → 庫存 → 購物車明細 → 價格批次。
3. 重查價格與庫存；總額與結帳頁顯示的不同時中止，請會員確認新金額。
4. 扣庫存。
5. 建立訂單、訂單明細與收件快照（商品名稱、SKU、單價、數量、小計、運費規則），並建立「待出貨」的出貨單。
6. 刪除購物車明細，價格批次剩餘量歸零；寫入訂單歷程「成立訂單」。
7. 提交後寄出訂單成立通知信；寄信失敗不影響訂單。

**其他規則**

- **防重複送出**：一次性結帳憑證、30 分鐘有效，存在訂單的唯一鍵；同一憑證再送出只會導向已成立的訂單。
- **訂單編號**：`S` + 下單日期 + 6 位流水號，例如 `S20261121-000123`。
- **價格變動**：結帳頁提示；訂單以結帳當下的價格為準。

## 11. 訂單狀態與歷程（第四階段）

訂單主狀態有五種（第六階段加上線上付款用的「待付款」，第 31 節）；會員按「我已收到」或出貨滿 3 天自動完成，退換貨另由售後單處理（第 12 節）。

| 狀態 | 代碼 | 進入方式 | 後續處理 |
| --- | --- | --- | --- |
| 處理中 | `processing` | 下單成立，同時建立待出貨的出貨單 | — |
| 已出貨 | `shipped` | 倉庫完成出貨單 | 開始計算自動完成天數 |
| 訂單完成 | `completed` | 會員按「我已收到，完成訂單」；出貨滿自動完成天數（預設 3 天，可設 1～14）；管理員標記；會員在已出貨時申請退換貨 | 記錄完成時間與完成者；退換貨期限起算；累積消費加上商品小計並重算等級 |
| 取消 | `cancelled` | 處理中時會員或管理員取消 | 立即回補庫存；待出貨的出貨單作廢 |
| 拒收 | `refused` | 已出貨時管理員標記（需填原因） | 產生「拒收退回」收件單，驗收後才回補庫存；不產生退款 |

- 只允許上表的轉換；已完成的訂單不能再改為拒收。
- **自動完成不用排程**：會員或管理員開啟訂單相關頁面時，系統順便把「已出貨、未暫停、出貨已滿設定天數」的訂單分批完成，每次最多 50 筆，歷程記為「系統自動完成」。
- **暫停自動完成**：管理員可對個別訂單暫停（例如物流回報異常）。
- 取消、拒收的訂單不計入累積消費。

**會員看到的訂單狀態**

| 會員看到的 | 會員可以做的事 |
| --- | --- |
| 處理中 | 取消訂單 |
| 已出貨 | 查看物流商、追蹤碼與出貨日；按「我已收到，完成訂單」；申請退貨或換貨 |
| 已完成 | 在期限內申請退貨或換貨，顯示剩餘天數 |
| 已取消／拒收 | 無 |

有售後時在訂單上附加摘要，例如「已完成（2 項換貨處理中）」。

**訂單歷程**：每次狀態轉換（含自動完成）、出貨單與收件單異動、售後單異動與備註都寫一筆，記錄時間、類型、原狀態 → 新狀態、操作者（會員、管理員或系統）、給會員看的說明與內部備註。會員訂單頁以時間軸顯示，內部備註只在後台顯示。

訂單完成後才能接到售後單；換貨的新品要等倉庫驗收收回的商品後才寄出。

## 12. 退換貨（第四階段）

會員收到貨後，可在期限內對整單或個別商品按「退貨」或「換貨」進入申請程序；每次申請成為一張售後單，一次只能是一種類型。

**期限**

- 「退換貨天數」預設 7 天，可設 7～90 天；自訂單完成時間起算，到期日當天 23:59:59 截止。
- 下限 7 天，對應消保法第 19 條通訊交易的 7 日解除權；結帳頁與訂單頁要以清楚易懂的文字標示期限與申請方式（[行政院消保處函釋](https://www.ey.gov.tw/Page/8F51FEE53AB45EA9/36663b43-67df-4bdb-b8f7-d6a649b95223)）。上線前建議請法律人員確認。

**退貨程序**

1. 選品項與數量：「整單退貨」預先勾好全部可申請數量；品項旁的「退貨」只帶入該品項，數量可調整。
2. 選原因（商品瑕疵、與描述不符、不想要了、其他，必選），填說明（選填，最多 500 字）。
3. 確認預估退款：退回商品小計；整單退貨（含分次退完）再加運費與手續費。貨到付款由客服聯繫退款，不收銀行帳號。
4. 送出，顯示售後單編號；核准後收到寄回說明信。

**換貨程序**

1. 選品項與數量（整單或個別）；只能換同一項商品、同樣數量。
2. 選原因並填說明。
3. 選新品寄送地址：預設原訂單地址，可從地址簿另選。
4. 送出，顯示售後單編號；核准後收到寄回說明信。

**申請規則**

- 在「已出貨」申請時，同一筆交易內先完成訂單（完成者為會員），再建立售後單。
- 可申請數量 = 購買數量 − 已退貨完成 − 進行中售後單的數量。
- 退貨與換貨不能混在同一張申請；同一訂單可有多張售後單。
- 「申請審核中」時可撤回；核准後可選填寄回的物流商與單號。

**會員看到的售後進度**

| 階段 | 內部狀態 | 退貨顯示 | 換貨顯示 |
| --- | --- | --- | --- |
| 送出申請 | 申請中 | 申請審核中 | 申請審核中 |
| 客服核准 | 退貨中／換貨中 | 請寄回商品 | 請寄回商品 |
| 倉庫驗收 | 退貨中／換貨中（收件單已完成） | 已收到退貨，退款處理中 | 已收到商品，新品準備中 |
| 結束 | 退貨完成／換貨完成 | 退貨完成（附退款金額與日期） | 新品已寄出（附追蹤碼） |
| 其他 | 已拒絕／已撤回 | 未核准（附原因）／已撤回 | 未核准（附原因）／已撤回 |

**退款（貨到付款）**：系統不線上退款、不存銀行帳號；倉庫驗收後客服才能登錄退款（金額、方式、日期、備註）；部分退貨不退運費；拒收不產生退款。

## 13. 後台單據：訂單處理與出貨處理（第四階段）

後台分成「訂單處理」（客服）與「出貨處理」（倉庫）：客服的操作只產生單據，貨物進出與回庫都在倉庫單據上完成；換貨 = 退貨收回＋再出貨。

| 單據 | 編號 | 類別 | 誰處理 | 類型 |
| --- | --- | --- | --- | --- |
| 訂單 | `S` + 日期 + 流水號 | 商務 | 客服 | — |
| 售後單（即退貨單與換貨單） | `R` + 日期 + 流水號 | 商務 | 客服 | 退貨、換貨 |
| 出貨單 | `D` + 日期 + 流水號 | 物流 | 倉庫 | 訂單出貨、換貨出貨 |
| 退貨收件單 | `I` + 日期 + 流水號 | 物流 | 倉庫 | 退貨收回、換貨收回、拒收退回 |

**單據流程**

1. **一般訂單**：下單，自動產生待出貨的出貨單 → 倉庫出貨，訂單變「已出貨」→ 會員確認或系統自動完成。
2. **退貨**：會員申請 → 客服核准，產生「退貨收回」收件單並寄出寄回說明 → 倉庫收件驗收、逐項決定是否回庫 → 客服登錄退款，退貨完成。
3. **換貨**：會員申請 → 客服核准，產生「換貨收回」收件單與「暫緩」的換貨出貨單（金額 0）→ 倉庫收件驗收，出貨單轉待出貨 → 倉庫寄出新品並扣庫存，換貨完成。
4. **拒收**：標記拒收，產生「拒收退回」收件單 → 倉庫收件驗收後回補庫存。

**後台頁面**

| 分組 | 頁面 | 功能 |
| --- | --- | --- |
| 訂單處理 | 訂單 `admin_orders.php` | 依狀態、日期、訂單編號、會員、收件人電話篩選，每頁 20 筆；詳情含明細、金額、歷程與關聯單據；取消、標記完成、標記拒收、暫停／恢復自動完成、內部備註 |
| 訂單處理 | 售後單 `admin_after_sales.php` | 依類型、狀態、日期篩選；核准、拒絕（填原因）、登錄退款（驗收後才可操作） |
| 出貨處理 | 出貨單 `admin_shipments.php` | 待出貨、暫緩、已出貨清單；填物流商（黑貓、新竹、郵局、其他）、追蹤碼、出貨日；A4 揀貨／出貨單可批次列印；一張訂單一張訂單出貨單，不分批 |
| 出貨處理 | 退貨收件單 `admin_receipts.php` | 待收件、已收件清單；顯示會員填的寄回單號；收件時逐項選「良品回庫」或「瑕疵不回庫」 |
| 設定 | 商場設定 `admin_settings.php` | 運費模式與規則、手續費、退換貨天數（7～90）、自動完成天數（1～14）、寄回地址、等級門檻與重新計算 |

庫存只在四個時點異動：下單扣除、出貨前取消回補、收件單良品回庫、換貨出貨單寄出時扣除。

## 14. 會員等級與累積消費（第四階段）

會員等級依終身累積消費自動計算；管理員可以鎖定個別會員的等級。等級本階段不提供折扣或運費優惠。

| 等級 | 預設門檻（元） |
| --- | --- |
| 一般 | 0（固定） |
| 銀卡 | 3,000 |
| 金卡 | 10,000 |
| 鑽石 | 30,000 |

- 門檻可在後台修改，必須由低到高遞增。
- **累積消費** = 已完成訂單的商品小計（不含運費與手續費），退貨完成時扣除退回金額；其他狀態的訂單不計。
- **重算時機**：訂單完成（含自動完成）、退貨完成時，同一筆交易內更新並寫入等級變動紀錄。
- **降級**：只有退貨完成使累積消費低於目前等級門檻時才降，其他情況只升不降。
- **手動鎖定**：鎖定者不參與自動計算（累積消費照常更新），解除後下一次重算套用。
- **門檻變更**：存檔不立即套用；按「重新計算全部會員」先預覽受影響人數與名單再執行，只升不降。
- 第三階段事件已保存事件當時的等級，重算不影響歷史報表。
- 會員中心顯示目前等級、累積消費與距下一級差額（鎖定者不顯示差額）。

## 15. 公開資訊與購物須知（第五階段）

營運者名稱、客服聯絡方式與三份公開文件由管理員在後台「聲明與購物須知」頁修改，前台各頁自動顯示最新內容。

| 欄位 | 上限 | 顯示位置 |
| --- | --- | --- |
| 公開營運者名稱 | 100 字 | 頁尾、各公開文件頁、通知信署名 |
| 公開客服／個資權利聯絡方式 | 1,000 字 | 頁尾、個資保護聲明與退貨條款頁、售後核准信 |
| 個資保護聲明 | 20,000 字 | `privacy.php`；Cookie 橫幅、註冊頁、結帳頁連結 |
| 退貨條款 | 20,000 字 | `returns.php`；結帳頁、訂單頁、退換貨程序連結 |
| 使用者購物須知 | 20,000 字 | `shopping-guide.php`；結帳頁、頁尾連結 |

- **格式**：純文字儲存、輸出時編碼；空行分段，網址自動成為連結；不接受 HTML。
- **佔位字**：文件內可用 `{營運者名稱}`、`{退換貨天數}`、`{自動完成天數}`、`{貨到付款手續費}`，顯示時代入目前設定，讓條款與實際設定一致。
- **版本**：每份文件記錄最後更新時間，頁面顯示「最後更新：YYYY-MM-DD」；修改寫入異動紀錄（含異動前後全文）。
- **預設範本**：安裝時提供依本系統（貨到付款、退換貨流程、運費規則、Cookie 選項）撰寫的範本，並標示「請依實際營運修改，並請法律人員確認」。
- **未填寫時**：營運者名稱或客服聯絡方式空白時，後台首頁提醒，結帳頁停用送出並顯示「商店資訊尚未設定」（決策 27）。

**頁尾**：每頁頁尾顯示「個資保護聲明 · 聯繫我們 · 退貨條款 · 購物須知 · Cookie 設定」，並附營運者名稱與客服聯絡方式。

## 16. Cookie 同意與 Consent Mode v2（第五階段）

訪客第一次進站會看到「Cookie 與隱私設定」：必要 Cookie 一律啟用，分析與廣告預設拒絕；選擇以 Google Consent Mode v2 傳給 Google 標籤（[Google 設定說明](https://developers.google.com/tag-platform/security/guides/consent)）。

| 訪客看到的選項 | Consent Mode 參數 | 預設值 |
| --- | --- | --- |
| 必要 Cookie（不能關閉） | `security_storage`、`functionality_storage` | granted |
| 允許分析統計 | `analytics_storage` | denied |
| 允許廣告資料與個人化 | `ad_storage`、`ad_user_data`、`ad_personalization` | denied |

**訪客端**

- 對話框：說明文字、兩個勾選項（預設不勾）、個資保護聲明連結，以及「僅必要 Cookie」「儲存選擇」「全部同意」三個按鈕。
- 點擊外側、按 Esc 或「收合」只收起，不代表同意。
- 每頁底部固定「Cookie 設定」按鈕可重新開啟；可用鍵盤操作，具 ARIA 標記。
- 選擇存在第一方 Cookie `shop_consent`（版本、兩項選擇、時間），180 天後或同意版本更新時重新詢問；不寫入資料庫（決策 24、25）。
- 同意前只寫必要 Cookie：登入 Session 與 `shop_consent` 本身。

**頁面載入順序（每一頁）**

1. `<head>` 最前面輸出 `gtag('consent','default', …)`：分析與廣告四項 denied、`wait_for_update: 500`；依設定加上 `url_passthrough`、`ads_data_redaction`。
2. Cookie 已有有效選擇時，立刻送出 `gtag('consent','update', …)`。
3. 依各段載入條件輸出自訂程式碼（第 17 節）。
4. 訪客做選擇時送出 `update`、推送 `dataLayer` 事件 `consent_update`，並啟用等待同意的程式碼，不必重新整理。

**實作模式**（決策 22：後台可切換，預設進階）：基本模式在取得同意前封鎖標籤；進階模式先以預設值載入標籤，再依同意調整行為（[Google 概觀](https://developers.google.com/tag-platform/security/concepts/consent-mode)）。本系統中，載入條件為「Google 標籤」的程式碼：進階模式一律載入，基本模式在取得任一同意後才載入。

**後台「Cookie 橫幅與重設」**

- 自動顯示橫幅：關閉只取消自動彈出，底部按鈕仍可開啟；未選擇時分析與廣告維持拒絕。
- 標題與說明文字、個資保護聲明連結（預設 `privacy.php`）、實作模式、`url_passthrough`、`ads_data_redaction`。
- 還原預設：需先勾選「我確認要還原預設」；恢復自動顯示與四項預設拒絕，同意版本加一使原選擇失效；不清除會員登入或購物車；現有頁面須重新載入才套用。
- 後台頁不顯示橫幅，但照常輸出同意預設與更新指令，沿用同一個 Cookie 的選擇。
- 台灣訪客為主，不做依地區的預設值（`regions`）。
- 第三階段會員行為紀錄不受此同意控制（決策 23）。

## 17. 自訂程式碼（第五階段）

管理員可以新增多段自訂程式碼，指定插入位置、套用模組與載入條件；GTM、GA4、Google Ads 等標籤都用這個功能加入（決策 21）。

| 欄位 | 選項與規則 |
| --- | --- |
| 名稱 | 1～50 字 |
| 插入位置 | `<head>` 後、`</head>` 前、`<body>` 後、`</body>` 前 |
| 套用模組 | 前台與會員頁（含登入、購物車、結帳、會員中心、前台錯誤頁）／後台頁／兩者 |
| 載入條件 | 一律載入／Google 標籤（依 Consent Mode 模式）／需分析同意／需廣告同意 |
| 排序 | 同一位置依數字由小到大輸出 |
| 啟用 | 開／關 |
| 程式碼 | 最多 64 KB |

- `<head>` 後的程式碼排在 Consent Mode 預設指令之後，確保預設值最先執行。
- 需等待同意的程式碼以 `type="text/plain"` 加同意分類屬性輸出，取得同意後由頁面腳本轉為可執行；這類程式碼只能包含 `<script>` 區塊，存檔時驗證。
- 程式碼原樣輸出、不編碼，只有管理員可以編輯；存檔寫入異動紀錄（含異動前後全文）。
- 後台列表顯示每段會出現在哪些頁面的哪個位置。
- **安全模式**：管理者在網址加 `?no_custom_code=1` 時，該次請求不輸出任何自訂程式碼；`config.php` 的 `$disable_custom_code` 可全站停用，供程式碼導致後台無法操作時使用。

## 18. 寄信紀錄（第五階段）

每一封系統信，不論成功或失敗，都寫一筆寄信紀錄；失敗原因只在後台看得到，訪客畫面只顯示一般訊息。

- **記錄欄位**：時間、信件類型、收件 Email、主旨、結果（成功／失敗）、錯誤訊息（PHPMailer `ErrorInfo`，最多 1,000 字）、關聯會員／訂單／售後單、耗時毫秒。
- **信件類型**：註冊驗證、補寄驗證、後台補寄驗證、重設密碼、訂單成立、已出貨、訂單取消、售後核准、售後拒絕、退貨完成、換貨新品寄出、聯繫確認信、客服回覆、測試信。
- **不儲存**：信件內文與連結（驗證與重設連結含憑證）。
- **後台頁** `admin_mail_logs.php`：依類型、結果、日期、Email 篩選，每頁 50 筆，失敗紀錄醒目標示；設定頁有「寄測試信」按鈕驗證 SMTP。
- **保留**：180 天；開啟後台頁面時被動刪除過期紀錄，每次最多 500 筆。
- 寄信在交易提交後進行，失敗不影響訂單或售後單。

## 19. 備份與還原（第五階段）

後台可以下載完整 JSON 備份，並在隔離資料表做還原演練；演練驗證通過後，才能套用為正式資料。

**下載完整備份**

- 包含所有商場資料表（會員、商品、庫存、購物車、訂單與單據、稽核、設定、公開文件、自訂程式碼等）；行為事件與封存月份表預設不含、可勾選包含（決策 30）。
- 格式為 gzip 壓縮的 JSON（`.json.gz`）：meta 記錄產生時間、程式版本、資料庫版本，以及每表的欄位、筆數與 SHA-256；以串流輸出，避免記憶體不足。
- 檔案含個資與密碼雜湊，下載前須再次輸入管理員密碼並勾選確認；下載寫入異動紀錄。不含 `config.php` 與 SMTP 帳密。

**隔離還原演練**

- 上傳備份後，在 `dr_` 開頭的隔離資料表還原（例如 `dr_20261121_0930_members`），不修改正式資料。
- 逐表驗證筆數、欄位與 SHA-256；結果寫入演練紀錄（編號、隔離名稱、資料表數、資料列數、結果、時間）。
- 分批處理：每次請求處理一段、未完成時自動接續，避開主機執行時間限制。
- 演練表保留供檢查，可在後台刪除指定演練的隔離表。

**套用為正式資料**（決策 26）

- 只有驗證通過、且資料表結構與目前程式版本相同的演練可以套用；需輸入確認字句與管理員密碼。
- 套用期間網站進入維護模式，前台顯示維護中，只有管理者可操作。
- 以單一 `RENAME TABLE` 原子交換：正式表改名為 `bak_<時間>_` 保留，演練表改名為正式表；交換後補建外鍵並檢查，失敗時以同樣方式換回。
- InfinityFree 的上傳大小與執行時間限制須在主機實測；超過上限的備份改用 phpMyAdmin 匯入。

## 20. 管理員 IP 白名單（第五階段）

白名單有任一啟用項目時，只有符合的 IP 才能使用管理功能；清單為空時不限制。

- **項目**：IP 或 CIDR（IPv4、IPv6，例如 `203.0.113.5`、`203.0.113.0/24`）、說明、啟用、建立者與時間；異動寫入異動紀錄。
- **範圍**：所有後台頁面與後台寫入；IP 不符時不輸出後台選單、開啟後台頁回應 403；管理者帳號仍可在前台購物。
- **防止鎖死**：頁面顯示「你目前的 IP」；存檔後若目前 IP 不在清單內則拒絕存檔；`config.php` 的 `$disable_admin_ip_allowlist` 可緊急暫停。
- **IP 判斷**：預設用 `REMOTE_ADDR`；主機在代理後方時，於 `config.php` 設定信任的代理 IP 與標頭（例如 `X-Forwarded-For`、`CF-Connecting-IP`），未設定時不採信任何標頭。InfinityFree 實際取得的位址須在主機驗收確認。
- **安全紀錄**：被拒存取寫入安全紀錄（時間、IP、會員、頁面），同一 IP 每分鐘最多一筆；後台可查詢。

## 21. 辨識碼驗證（第五階段）

前台與會員中心所有需要填寫並送出的表單，以及後台登入，都要輸入自建的圖片辨識碼（決策 31、32）。

- **適用表單**：註冊、登入（含管理者）、忘記密碼、補寄驗證信、重設密碼、會員中心改姓名與改密碼、新增或修改地址、結帳、退換貨申請、聯繫表單、客服中心。
- **不適用**：加入購物車、修改數量、移除、Cookie 選擇、登出、後台登入後的編輯表單；這些仍有 CSRF 與 `row_version` 保護。
- **做法**：PHP GD 產生 5 字元圖片，排除 0／O、1／I 等易混淆字元；每張表單各自產生、存在 Session（只存雜湊）、10 分鐘有效、只能用一次、不分大小寫；提供「換一張」與替代文字。
- **錯誤處理**：辨識碼錯誤時保留已填寫的內容（密碼欄除外）並換新圖；同一 Session 連續錯 10 次需等 5 分鐘。
- **後端先驗**：先檢查 CSRF 與辨識碼，通過後才驗證其他欄位與寫入。
- **主機需求**：需要 PHP GD 擴充；若主機沒有 GD，改用簡單的算術題文字辨識。

## 22. 管理員權限模組（第五階段）

後台分成七個模組，系統管理者擁有全部權限，其他管理員由系統管理者逐模組授權「檢視」或「編輯」；編輯包含檢視。

| 模組 | 涵蓋功能 | 檢視 | 編輯 |
| --- | --- | --- | --- |
| 系統管理者 | 全部功能；管理員帳號與授權；異動紀錄、寄信紀錄、Cookie 與 Consent Mode、自訂程式碼、公開資訊、商場設定（手續費、退換貨與自動完成天數、寄回地址）、備份還原、IP 白名單、行為資料維護；第六階段：商店與 SEO 設定、付款與配送設定、模擬門市、維護模式、錯誤紀錄、寄信額度、資料清理 | — | 全部 |
| 商品管理 | 商品、分類、標籤、庫存、運費規則；商品圖片、規格（SKU）、商品與分類 SEO 欄位、不可超商取貨標記 | 清單與內容 | 新增、修改、刪除、調整庫存 |
| 會員管理 | 會員資料、狀態、等級、等級門檻與重算、鎖定等級、刪除帳號申請 | 會員與其訂單摘要 | 修改、停權、刪除、補寄驗證信、核准刪除申請並匿名化 |
| 訂單處理 | 訂單、售後單、退款登錄、付款狀態 | 訂單與售後單 | 取消、標記完成或拒收、暫停自動完成、審核、登錄退款、模擬線上退款 |
| 出貨處理 | 出貨單、退貨收件單、揀貨單列印、超商物流狀態 | 清單與收件資料 | 出貨、收件驗收、標記已到店／已取貨／未取貨退回 |
| 客服及聯繫表單 | 訊息中心 | 訊息與處理紀錄 | 接手處理、寫處理摘要、回覆客戶、改狀態 |
| 報表分析 | 行為報表、總覽的瀏覽行為曲線 | 查詢報表 | —（唯讀模組） |

- **帳號**：系統管理者在「管理員與權限」頁從已啟用、已驗證的會員中指定管理員，勾選各模組的檢視／編輯，或設為系統管理者；取消全部權限即回到一般會員。
- **保護規則**：只有系統管理者能授權；不能變更自己的權限；不能停權、刪除或變更註冊時間早於或等於自己的系統管理者；至少保留一位啟用中的系統管理者。會員管理模組不能停權或刪除任何管理員。
- **顯示**：管理員只看到有權限的選單、頁面、按鈕與總覽卡片；只有檢視權限時，頁面不輸出寫入表單。
- **後端檢查**：每個後台頁面與寫入都從資料庫核對模組權限，不足時回應 403；`admin_transaction()` 鎖定操作者時一併重新確認權限。
- **紀錄**：授權變更寫入異動紀錄（誰、何時、對誰、變更前後）。
- **升級**：既有 `is_admin = 1` 的管理者自動成為系統管理者。

## 23. 管理總覽（第五階段）

管理員登入後的首頁是「管理總覽」，只顯示有檢視權限的模組卡片；數字每次開頁即時查詢，卡片可點進對應的後台頁面。

| 卡片 | 內容 | 需要的權限 |
| --- | --- | --- |
| 會員 | 會員總數、近 30 天新增、待驗證、各等級分布（長條圖） | 會員管理 |
| 商品 | 上架數、缺貨數、低庫存清單（庫存 ≦ 5） | 商品管理 |
| 訂單 | 今日與近 30 天的訂單數與金額、各狀態筆數 | 訂單處理 |
| 退換貨 | 申請中、退貨中、換貨中筆數 | 訂單處理 |
| 出貨與收件 | 待出貨、暫緩、待收件筆數 | 出貨處理 |
| 訊息 | 未處理、處理中筆數，最舊未處理訊息的等待時間 | 客服及聯繫表單 |
| 瀏覽行為曲線 | 近 30 天每日瀏覽次數與加入購物車次數（折線圖） | 報表分析 |
| 系統提醒 | 公開資訊未填、分區未準備、可封存月份、近 7 天寄信失敗筆數 | 系統管理者 |

- 圖表由伺服器產生 SVG，不載入外部圖表套件；圖表旁附數字表格，供輔助科技閱讀。
- 金額以訂單總額計，取消與拒收不計入；日期以台灣時間分日。
- 瀏覽行為曲線讀線上事件表，涵蓋已封存月份時依第 7 節規則合併去重。
- 開啟總覽時順便執行自動完成訂單、清除過期寄信紀錄等被動檢查。

## 24. 聯繫表單、客服中心與訊息中心（第五階段）

訪客用聯繫表單、會員用會員中心的客服中心發問，兩者都進入後台訊息中心，記錄誰處理、處理摘要、來源 IP 與狀態。

**聯繫表單 `contact.php`（訪客）**

- 欄位：姓名、Email（必填）、電話（選填）、類別（商品詢問、訂單問題、退換貨、帳號問題、其他）、主旨（1～100 字）、內容（10～2,000 字）。
- 送出前須勾選同意個資保護聲明並輸入辨識碼；同一 IP 每小時最多 5 則。
- 送出後顯示訊息編號（`M` + 日期 + 流水號），並寄確認信給填寫的 Email。

**客服中心（會員中心內）**

- 欄位與聯繫表單相同；姓名與 Email 自動帶入會員資料，可選擇相關訂單。
- 會員可以看到自己送出過的訊息、處理狀態與客服回覆（不含內部處理摘要）。
- 登入中的會員開啟聯繫表單時，提示可改用客服中心。

**後台訊息中心 `admin_messages.php`**

- 狀態：未處理（新訊息）→ 處理中（客服按「接手」，記錄處理人）→ 已處理；已處理可重新開啟為處理中（決策 34）。
- 清單依狀態、來源（訪客／會員）、類別、處理人、日期篩選，每頁 30 筆；未處理的排在最前。
- 詳情顯示內容、來源 IP、送出時間；會員來源另顯示會員編號、等級、訂單數與所選訂單，有權限時可連到會員與訂單頁。
- **處理摘要**：只給內部看，可多次新增，每筆記錄處理人與時間。
- **回覆客戶**：送出時寄信給客戶，會員也能在客服中心看到（決策 35）。
- 每次狀態變更、接手、摘要與回覆都寫入訊息歷程（誰、何時、做了什麼）。

## 25. 會員申請刪除帳號與資料匿名化（第六階段）

會員在會員中心申請刪除帳號，申請出現在後台會員管理；管理員確認訂單相關處理都結案後執行軟刪除，系統同時清除個人資料，只留下維持關聯所需的資訊。

**會員端**

- 會員中心「刪除帳號」：輸入密碼、辨識碼，並勾選「我了解刪除後無法復原」；可填原因（選填）。
- 若有仍在退換貨期限內的訂單，申請頁提醒「刪除後將無法申請退換貨」。
- 申請後帳號仍可使用（以便處理未完成的訂單），管理員處理前可自行取消申請。
- 申請時、被拒絕時、刪除完成時各寄一封信；完成信在匿名化前寄到原 Email。

**後台（會員管理）**

- 會員清單可篩選「刪除申請」；申請狀態為待處理、已拒絕（附原因）、已完成、已取消。
- 軟刪除前系統自動檢查，任一項未結案就停用「執行刪除」並列出阻擋項目：
  - 訂單為待付款、處理中或已出貨；
  - 售後單為申請中、退貨中或換貨中，或已退貨但尚未登錄退款；
  - 出貨單待出貨或暫緩、收件單待收件；
  - 客服訊息為未處理或處理中。
- 執行刪除需要「會員管理」編輯權限；管理員帳號須先由系統管理者取消權限才能刪除。

**匿名化內容（同一筆交易）**

| 資料 | 處理方式 |
| --- | --- |
| 會員帳號 | 姓名改為「已刪除會員」；Email 改為 `deleted-<編號>@deleted.invalid`（同一 Email 之後可重新註冊）；密碼雜湊改為無法登入的隨機值；清除驗證與重設憑證；狀態停用、記錄 `deleted_at` 與匿名化時間 |
| 地址簿 | 全部刪除 |
| 訂單、出貨單、換貨售後單的收件快照 | 姓名、電話、郵遞區號、鄉鎮區、詳細地址清除；保留縣市供區域統計 |
| 訂單備註、寄回物流單號 | 清除 |
| 客服訊息 | 姓名、Email、電話、主旨、內容與客服回覆清除；類別、狀態、時間、內部處理摘要保留（摘要請勿寫入個資） |
| 寄信紀錄 | 收件 Email 遮蔽（例如 `m***@***`） |
| 異動紀錄、安全紀錄 | 該會員的姓名、Email、電話、地址欄位改為「\[已刪除\]」；IP 清除 |
| 購物車、價格批次 | 購物車明細清空 |
| 保留 | 會員編號、訂單編號與金額、商品明細、狀態與歷程、行為事件（只含編號）、等級變動紀錄 |

帳務應保存的交易資料與期限，請向會計師確認。

## 26. SEO：meta、canonical、noindex、robots.txt、sitemap.xml（第六階段）

每個商品與分類都可以編輯搜尋結果與社群分享用的標題、說明與圖片；不該被收錄的頁面自動加上 `noindex`，`robots.txt` 與 `sitemap.xml` 由系統自動產生。

**可編輯欄位**

| 對象 | 欄位 | 未填時的預設值 |
| --- | --- | --- |
| 商品 | SEO 標題（最多 100 字）、meta description（最多 200 字）、OG 圖片（從商品圖片中選） | 「商品名稱｜站名」、商品說明前 120 字、主圖 |
| 分類 | SEO 標題、meta description、OG 圖片（上傳）、分類說明（顯示在分類頁上方） | 「分類名稱｜站名」、分類說明前 120 字、站台預設 OG 圖 |
| 首頁與全站 | 首頁標題、首頁說明、預設 OG 圖（在後台「商店與 SEO 設定」） | 站名 |

編輯頁顯示字數與搜尋結果預覽。

**canonical**

- 商品頁：`product.php?id=<編號>`，去除追蹤參數與 `_cart_return` 等系統參數。
- 分類頁：`products.php?category=<編號>`，第 2 頁起帶 `page`；標籤篩選與分類組合的頁面 canonical 指回該分類。
- 首頁與公開文件頁指向自己。

**noindex**

- 加 `noindex, follow`：購物車、結帳、付款、會員中心與我的訂單、登入、註冊、忘記密碼、重設密碼、驗證頁、站內搜尋結果、下架商品。
- 後台所有頁面加 `noindex, nofollow` 與 `X-Robots-Tag` 標頭。
- 維護模式回應 503（第 32 節），不影響既有收錄。

**robots.txt 與 sitemap.xml**

- 由 `.htaccess` 將 `/robots.txt`、`/sitemap.xml` 導向 PHP 動態產生。
- `robots.txt`：擋下後台、購物車與結帳的寫入端點，列出 `Sitemap:` 網址；後台可加自訂規則。
- `sitemap.xml`：首頁、有上架商品的分類頁、上架商品（`lastmod` 為更新時間，附商品圖片）、公開文件頁。不列 noindex 的頁面。
- InfinityFree 的瀏覽器安全檢查可能影響部分檢測工具，上線前需用 Search Console 實測（第 39 節）。

## 27. 結構化資料、Open Graph 與 Twitter Card（第六階段）

首頁、商品列表頁與商品頁自動輸出 JSON-LD；運費規則與退換貨天數直接轉成運送與退貨政策標記（[Google 商家資訊標記](https://developers.google.com/search/docs/appearance/structured-data/merchant-listing)、[退貨政策標記](https://developers.google.com/search/docs/appearance/structured-data/return-policy)）。

| 頁面 | schema.org 類型 | 主要內容 |
| --- | --- | --- |
| 首頁 | `OnlineStore`（Organization）、`WebSite` | 名稱、法定名稱、網址、Logo、客服聯絡（`contactPoint`）、社群連結（`sameAs`）、統一編號（`taxID`，選填）、`hasMerchantReturnPolicy` |
| 商品列表頁（分類頁） | `ItemList`、`BreadcrumbList` | 該頁商品的順序與網址；首頁 > 分類 |
| 商品頁 | `Product`（有規格時為 `ProductGroup` + `hasVariant`）、`BreadcrumbList` | 名稱、圖片、說明、SKU、品牌；`Offer` 的價格、TWD、庫存狀態（InStock／OutOfStock）、`itemCondition`；`shippingDetails`（依運費規則與配送方式產生運費、免運門檻、臺灣、處理與運送天數）、`hasMerchantReturnPolicy`（退換貨天數、郵寄退回、退貨運費負擔） |

**Open Graph 與 Twitter Card**（首頁、分類頁、商品頁、公開文件頁）

- `og:type`（首頁與列表為 website、商品為 product）、`og:title`、`og:description`、`og:image`（建議 1200×630）、`og:url`、`og:site_name`、`og:locale`（zh\_TW）；商品頁加 `product:price:amount` 與 `product:price:currency`。
- `twitter:card`（summary\_large\_image）、`twitter:site`、`twitter:title`、`twitter:description`、`twitter:image`。
- 內容取自第 26 節的 SEO 欄位與預設值。

**後台「商店與 SEO 設定」輸入的資訊**（只限系統管理者）

- 商店名稱、法定名稱、統一編號（選填，填寫後也顯示在頁尾）、Logo、預設 OG 圖、客服 Email 與電話、地址（選填）、社群連結（每行一個）、X（Twitter）帳號、預設品牌名稱。
- 處理天數與運送天數（宅配、超商各自的最少～最多天數）、退貨運費負擔（商店負擔／顧客負擔）。
- 商品可另填品牌（未填用預設品牌）與 GTIN（選填）。

**規則**：JSON-LD 以 `json_encode` 產生並跳脫 `</script>`；只輸出頁面上看得到的資訊；下架商品不輸出 `Offer`。

## 28. GA4 電子商務 dataLayer（第六階段）

每頁在 Consent Mode 預設指令之後、自訂程式碼執行之前，先推送頁面資訊與電子商務事件到 `dataLayer`，讓 GTM 的 GA4 標籤可以直接使用。

**頁面載入順序**：Consent Mode 預設與更新 → `dataLayer` 頁面資訊與事件 → 自訂程式碼（含 GTM）。

| 事件 | 觸發頁面或時機 | 主要參數 |
| --- | --- | --- |
| `view_item_list` | 首頁最新上架、商品列表頁 | `item_list_id`、`item_list_name`、`items` |
| `view_item` | 商品頁（上架商品） | `currency`、`value`、`items` |
| `add_to_cart` | 加入成功後回到的頁面 | `currency`、`value`、`items`（本次加入數量） |
| `remove_from_cart` | 移除或調減成功後回到的頁面 | 同上（本次減少數量） |
| `view_cart` | 購物車頁 | `currency`、`value`、`items` |
| `begin_checkout` | 結帳頁 | `currency`、`value`、`items` |
| `add_shipping_info` | 結帳頁選定配送方式時 | `shipping_tier`（宅配／超商） |
| `add_payment_info` | 結帳頁選定付款方式時 | `payment_type` |
| `purchase` | 貨到付款：下單成功頁；線上付款：付款成功頁 | `transaction_id`（訂單編號）、`value`、`shipping`、`currency`、`items` |

- **items 內容**：`item_id`（規格 SKU）、`item_name`、`item_brand`、`item_category`、`item_variant`（例如「紅色 / M」）、`price`、`quantity`；幣別 TWD。
- 每次推送電子商務事件前先推送 `{ecommerce: null}` 清除上一筆。
- POST 後重新導向的事件（加入、移除、下單）先存入 Session 的一次性佇列，在下一頁輸出後清除；`purchase` 以訂單欄位記錄已推送，重新整理不重複。
- 頁面資訊只推送頁面類型與是否登入，不推送姓名、Email、電話等個資。
- `dataLayer` 只是資料，是否寫 Cookie 或送出由 GTM 內的標籤依 Consent Mode 決定。
- 退款（`refund`）發生在後台，不在前台推送。

## 29. 商品圖片上傳（第六階段）

每個商品可上傳多張圖片，系統產生大圖與縮圖；第一張為主圖，用於列表、購物車、訂單、OG 與結構化資料。

- **限制**：每個商品最多 10 張；JPG、PNG、WebP；單檔最大 5 MB（受主機上傳上限限制）。
- **驗證**：以實際圖片內容判斷格式，不信任副檔名；重新編碼儲存，去除 EXIF 等元資料（含 GPS）。
- **尺寸**：大圖最長邊 1200 px、縮圖 400 px；主機支援時存成 WebP。
- **儲存**：`uploads/products/` 下以隨機檔名儲存；該目錄以 `.htaccess` 禁止執行 PHP。
- **管理**：拖曳或上下移動調整順序、設為主圖、編輯替代文字（alt，未填時以商品名稱代入）、刪除；可指定圖片對應的規格（例如某個顏色），前台切換規格時顯示對應圖片。
- **前台**：商品頁主圖與縮圖列；圖片帶 `width`、`height` 與 `loading="lazy"`（主圖除外）。無圖商品使用共用示意圖。
- **分類 OG 圖**與商店 Logo、預設 OG 圖使用同一套上傳與驗證規則。
- 刪除商品圖片時同步刪除檔案；備份檔不含圖片檔，圖片需以 FTP 另行備份。

## 30. 商品規格 SKU（第六階段）

商品可設最多兩種規格（例如顏色、尺寸），每個組合是一個規格 SKU；庫存、購物車與訂單都改以規格為單位。沒有規格的商品仍有一個預設規格，前台不顯示選項。

**後台（商品管理）**

- 在商品編輯頁設定規格名稱與選項值（例如顏色：紅、藍；尺寸：S、M、L），系統產生所有組合，最多 100 個。
- 每個規格：SKU（全站唯一）、價格（空白時用商品價格）、庫存、啟用、對應圖片（選填）、GTIN（選填）。
- 已被購物車或訂單使用的規格不能刪除，只能停用。
- 庫存頁逐規格列出與調整；商品搜尋也比對規格 SKU。

**前台**

- 商品頁選擇規格後顯示該規格的價格、庫存與圖片；缺貨或停用的組合選項反灰。
- 列表頁顯示價格區間（例如 NT$390～450）與是否還有庫存。

**影響其他階段**

- 購物車明細改以「購物車＋規格」唯一，可加入件數依規格庫存計算；價格批次仍掛在購物車明細上。
- 訂單明細存規格編號、規格 SKU 與規格文字快照；售後與換貨以訂單明細為單位，換貨仍限同一規格。
- 第三階段行為事件與六項排行維持以商品為單位，不分規格。
- 運費規則與「可否超商取貨」設在商品層級，所有規格共用。

**升級**：為每個既有商品建立一個預設規格（SKU 沿用商品 SKU），庫存轉入規格庫存，購物車與訂單明細補上預設規格編號；舊 `inventory` 表保留供回復、不再寫入。

## 31. 付款與配送方式：模擬線上支付與超商取貨（第六階段）

結帳時先選配送方式、再選付款方式；線上支付與超商取貨都是模擬流程，不連接真實金流與物流，也不收集任何卡號。

| 配送方式 | 可用付款方式 | 運費 | 貨到付款手續費 |
| --- | --- | --- | --- |
| 宅配 | 貨到付款、模擬信用卡、模擬 PayPal | 依商品運費規則（第 9 節） | 選貨到付款時收取 |
| 超商取貨（7-ELEVEN、全家、萊爾富、OK） | 超商取貨付款、模擬信用卡、模擬 PayPal | 後台設定的超商固定運費與免運門檻 | 選取貨付款時收取 |

- 商品可標記「不可超商取貨」（例如大型商品）；購物車含這類商品時停用超商取貨。
- 後台可個別啟用或停用每種配送與付款方式。
- **模擬門市**：內建範例門市清單（後台可新增、停用），結帳時依超商與縣市搜尋選取，代替真實電子地圖；訂單與出貨單存門市快照（超商、門市代號、名稱、地址）與取件人姓名、手機。

**付款狀態**（與訂單主狀態分開記錄）

| 付款狀態 | 說明 |
| --- | --- |
| 到付未收 | 貨到付款、超商取貨付款；訂單完成時轉為已付款 |
| 待付款 | 線上付款尚未完成 |
| 已付款 | 模擬付款成功或到付已收款 |
| 付款失敗 | 模擬付款失敗或取消，可重試 |
| 部分退款／已退款 | 線上付款訂單取消、退貨或未取貨後的模擬退款 |

**線上付款流程**

1. 送出訂單後，訂單為新的主狀態「待付款」（`pending_payment`）；庫存先扣，暂不產生出貨單。
2. 導向模擬付款頁 `pay_sim.php`：顯示金額與測試說明，只有「模擬付款成功」「模擬付款失敗」「取消」三個按鈕；付款請求以 HMAC 簽章防竄改（金鑰在 `config.php`）。
3. 成功：付款狀態已付款，訂單轉「處理中」並產生出貨單，推送 `purchase`，寄訂單成立信。
4. 失敗或取消：保持待付款，會員可在訂單頁重新付款。
5. 待付款超過 30 分鐘（後台可設 10～1,440 分鐘）以被動檢查自動取消並回補庫存。

- 每次付款嘗試寫一筆付款紀錄，重複的回報不重複處理。
- 付款程式以介面（gateway）實作，之後可換成綠界、藍新等真實金流。

**超商物流狀態**

- 超商出貨單：待出貨 → 已出貨 → 已到店 → 已取貨；已到店也可能「未取貨退回」。後台出貨處理手動模擬這些狀態。
- 會員端「已出貨」時另顯示「已到店，請於 YYYY-MM-DD 前取貨」（到店後 7 天）。
- 超商訂單不自動完成，以「已取貨」完成（後台標記或會員按「我已取貨」）；取貨付款同時轉為已付款。
- 未取貨退回：等同拒收，產生「拒收退回」收件單；線上已付款者驗收後模擬退款。

**退款**：線上已付款的訂單，取消、退貨完成或未取貨時以「原付款方式模擬退回」，更新付款狀態；貨到付款與超商取貨付款維持線下退款紀錄（決策 5）。

## 32. 維護模式（第六階段）

系統管理者可以一鍵開關全站維護模式；開啟時訪客與會員看到維護頁，管理員照常操作。

- **設定**：開／關、維護訊息（純文字）、預計結束時間（選填）；變更寫入異動紀錄。
- **訪客與會員**：前台所有頁面回應 HTTP 503 與 `Retry-After`，顯示維護訊息、頁尾公開文件連結與客服聯絡方式；所有前台寫入（購物車、結帳、發問等）一律拒絕。
- **仍可使用**：登入頁（供管理員登入）、`robots.txt`、模擬付款回報。
- **管理員**：有後台權限且符合 IP 白名單者可瀏覽前台與後台，頁面頂端顯示「維護模式中」提示。
- 備份套用（第 19 節）期間自動進入維護模式。

## 33. 錯誤紀錄檢視（第六階段）

免費主機不易取得 PHP 錯誤紀錄，系統自行記錄錯誤到資料庫，系統管理者可在後台查詢。

- **記錄範圍**：未捕捉例外、PHP 錯誤與警告、資料庫錯誤、寄信失敗以外的系統錯誤。
- **欄位**：第一次與最後一次發生時間、等級、訊息、檔案與行號、網址（去除憑證類參數）、請求方法、會員編號、IP、錯誤追蹤、發生次數。
- **合併**：同一訊息、檔案與行號只累加次數與更新最後時間，不重複新增。
- **不記錄**：密碼、憑證、CSRF 權杖、辨識碼等表單內容。
- **後台頁** `admin_error_logs.php`：依等級、日期、關鍵字篩選；可標記「已處理」；總覽的系統提醒顯示近 24 小時新錯誤數。
- **備援**：資料庫無法連線時改寫入帳號內非公開目錄的檔案，後台可一併檢視。
- **保留**：30 天（第 35 節）。

## 34. 寄信額度（第六階段）

由訪客觸發的信件依來源 IP 限量，額度在後台設定；超過時不寄出，畫面仍顯示一般訊息，避免被用來大量寄信或探測帳號。

| 設定 | 預設值 |
| --- | --- |
| 同一 IP 每小時 | 5 封 |
| 同一 IP 每日 | 20 封 |
| 同一收件 Email 每小時 | 3 封 |
| 全站訪客觸發信件每日上限 | 300 封（依寄信服務的每日限制調整） |

- **適用信件**：註冊驗證、補寄驗證、忘記密碼、聯繫確認信、客服中心發問。
- **不受 IP 額度限制**：訂單、出貨、售後等交易通知與後台寄出的信；全站上限只計算訪客觸發信件，為交易通知保留額度。
- 計數使用寄信紀錄（新增來源 IP 欄位）；超額時寄信紀錄記為「超過額度未寄出」，並寫一筆安全紀錄。
- 後台「寄信紀錄」頁顯示今日已用額度與超額的 IP。

## 35. 資料清理（第六階段）

系統定期清理長期沒動的購物車、過期 Session 與舊紀錄；因主機沒有排程，改在管理員開啟後台時被動執行，每小時最多一次、每項每次限量。

| 清理項目 | 預設保留 | 處理方式 |
| --- | --- | --- |
| 長期沒動的購物車 | 90 天未更新 | 清空明細、價格批次歸零；不寫入移出購物車事件 |
| 過期 Session | 超過 Session 有效時間 | Session 檔存在帳號內專用的非公開目錄，刪除逾期檔案 |
| 安全紀錄 | 180 天 | 刪除 |
| 錯誤紀錄 | 30 天 | 刪除 |
| 寄信紀錄 | 180 天 | 刪除 |
| 付款嘗試紀錄（未成功的） | 90 天 | 刪除；成功與退款紀錄隨訂單保留 |
| 備份演練的 `dr_` 表 | 30 天 | 刪除隔離表，保留演練紀錄 |

- 各項保留天數可在後台調整；後台「資料清理」頁顯示各項上次執行時間與清除筆數，可按「立即清理」。
- 每次清理寫入清理紀錄；不清理訂單、售後、異動紀錄與行為事件（行為事件由第三階段封存處理）。

## 37. 交付與驗收

每個階段交付完整 PHP、增量 SQL、範例資料 SQL、上傳清單、安裝與回復說明，以及在本機 MariaDB 與 PHP 上的測試報告；測試報告分列本機測試與主機驗收結果。

**第一～三階段**：已交付，本機 HTTP 與資料庫測試 154 項通過；主機上待驗收 SMTP 實際寄達與分區 DDL 權限。

**第四階段驗收**

- **地址**：10 筆上限、預設切換、刪除後快照不變、跨會員存取被拒。
- **運費**：第 9 節五個範例、全部免運、停用規則。
- **結帳**：價格變動中止、庫存不足、兩分頁同時送出只成立一張、下單後購物車清空且無新 `remove_from_cart`、自動產生出貨單。
- **訂單**：會員按完成、3 天自動完成（被動檢查）、暫停自動完成、不重複完成、各狀態轉換、取消立即回補、拒收驗收後才回補。
- **退換貨**：整單與個別（買 3 退 1）、已出貨申請時先完成訂單、逾期不能申請、混合申請被拒、驗收前不能退款、分次退完補退運費、換貨出貨單暫緩到驗收後、庫存不足不能寄出。
- **等級**：完成後升級、退貨後降級、鎖定不變、門檻變更預覽與只升不降。
- **交易回復**：模擬歷程寫入失敗，訂單、單據、庫存、購物車與累積消費全部回復。

**第五階段驗收**

- **公開資訊**：修改後前台即時顯示、佔位字代入目前設定、HTML 被編碼、未填時結帳停用、頁尾五個連結。
- **Cookie 同意**：三個按鈕的 Consent Mode 狀態在 Tag Assistant 正確、收合不等於同意、重新載入後維持選擇、180 天與版本更新後重問、基本與進階模式的載入差異。
- **自訂程式碼**：四個位置與三種套用模組、排序、需同意的程式碼在同意後才執行、安全模式與緊急停用。
